이 문서는 Iris Android 코드에 Z.AI GLM 외부 API 자동응답 모듈만 이식하기 위한 개발 범위와 검증 순서를 고정한다. 구현 중 Iris의 카카오 DB 감지·텍스트 발신 구조는 유지하고, `iris_bot` 또는 별도 Android 알림 리스너 앱을 런타임 필수 구성으로 추가하지 않는다.

## 개발 목적

- PD20에서 root로 실행되는 Iris가 카카오톡 수신 메시지를 감지하면, 허용된 채팅방의 명시적 AI 호출에 한해 Z.AI GLM Chat Completion API를 호출한다.
- 생성된 최종 텍스트만 기존 Iris `Replier.sendMessage()` 경로로 카카오톡에 발신한다.
- GLM API Key를 APK·Git·Iris 일반 설정 JSON에 포함하지 않고, 런타임 비밀 주입 경로로 분리한다.

## 개발 범위

- 현재 빌드 가능한 Iris 소스(`vendor/android`, 기준 커밋 `ee1dc978ec465df11642596e40f74caff497301d`)를 이식 대상 기준선으로 고정한다.
- `kakao_coreline_bot/android_client`에서 아래 책임만 Iris 구조에 맞게 이식한다.
  - Z.AI 요청/응답 DTO 및 HTTP 오류 분류
  - 시스템 프롬프트, 짧은 대화 이력, 응답 정리
  - 호출어·허용 채팅방·자기 메시지·중복 메시지 필터
- Z.AI 일반 Chat Completion API를 사용한다.
  - 기본 URL: `https://api.z.ai/api/paas/v4/chat/completions`
  - 현재 운영 모델은 `glm-4.5-flash`이며, 소스에 고정하지 않고 런타임 비밀이 아닌 설정값으로 지정한다. PD20 단문 SSE 실측 2회 평균 1.19초를 근거로 선정했다.
  - SSE `stream=true` 응답 청크를 내부에서 병합하고, 최종 응답 한 건만 전송한다.
- Iris의 `ObserverHelper` 복호화 메시지 이벤트에서 자동응답 핸들러를 호출하고, 기존 `Replier`로 답장을 보낸다.
- 방별 최근 4턴, 30분 만료의 휘발성 메모리를 사용한다. 앱/프로세스 재시작 후 이력은 보존하지 않는다.
- 단위 테스트, Iris APK 빌드, PD20 제한 E2E 테스트, 운영 문서 갱신을 포함한다.

## 문서 기반 제약 사항

- 현재 Iris의 텍스트 발신은 `NotificationActionService` 호출 경로를 사용하며, 이 계획은 해당 발신 코드를 교체하지 않는다.
- `Replier`의 발신 채널을 `Channel.BUFFERED`로 변경하고, GLM은 단일 순차 actor로 호출·발신을 위임해 동시 응답 유실을 막는다.
- Iris의 일반 설정 파일은 현재 시작 시 내용 전체를 로그에 출력한다. API Key/JWT를 이 파일에 저장하면 안 된다.
- PD20은 root 기기다. Android 클라이언트의 root 감지 차단 로직은 Iris 이식 대상이 아니며, Iris에는 별도 루팅 차단을 추가하지 않는다.
- 외부 GLM API 호출은 메시지와 제한된 대화 이력을 Z.AI 서비스로 전송한다. 자동 응답은 명시적 호출과 허용 방에서만 활성화한다.

## Phase 2. Z.AI GLM HTTP 클라이언트 이식

### 목표

- Android CBot의 GLM 요청 책임을 Iris에서 재사용 가능한 작은 클라이언트로 이식한다.

### 구현 태스크

- [x] 기존 Iris의 OkHttp와 Kotlin Serialization을 사용해 `GlmClient`를 구현한다.
- [x] `POST /chat/completions`, `Authorization: Bearer`, JSON `model/messages/temperature/max_tokens/stream=true` 요청을 구현한다.
- [x] GLM의 사고 과정은 전송·발신하지 않도록 `thinking` 비활성 요청과 최종 `message.content` 추출만 구현한다.
- [x] 401, 403, 429, 5xx, 네트워크 오류, 타임아웃, 빈 choices/body를 구분 가능한 내부 오류 타입으로 매핑한다.
- [x] 요청 ID, finish reason, 토큰 사용량은 관측용 메타데이터로만 유지하며 프롬프트·응답 원문은 기본 로그에 남기지 않는다.
- [x] 호출 시간 제한과 최대 출력 토큰을 설정값 또는 안전한 상수로 제한한다.

### 자체 테스트

- [x] Mock HTTP 서버로 URL, Bearer 헤더, 모델, 메시지, `stream=true` 및 SSE 청크 병합을 검증한다.
- [x] 정상 JSON에서 최종 `message.content`만 반환되는지 검증한다.
- [x] 401/403/429/5xx/타임아웃/빈 응답이 의도한 오류로 매핑되는지 검증한다.
- [x] 테스트 fixture와 로그에 실제 키·실제 대화 내용이 없는지 확인한다.

## 잔여 리스크 / 후속 과제

- 루팅된 단말에서는 장기 API Key를 완전히 보호할 수 없다. 운영 전 Token Broker 또는 Z.AI 단기 JWT 발급 구조를 별도 계획으로 구현한다.
- 카카오톡 내부 서비스와 DB 스키마 변경으로 Iris 발신·수신이 중단될 수 있으므로, 앱 업데이트 전 회귀 테스트가 필요하다.
- GLM API 비용·지연·사용량 제한은 실운영 관측 후 방별 쿨다운, 일일 한도, 운영 알림을 별도 범위로 추가 검토한다.
