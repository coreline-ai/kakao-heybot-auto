# implement_20260804_190757.md

작성 일시: `2026-08-04 19:07:57 KST`

이 문서는 PD20 카카오톡에 전송된 음성 파일을 한국어 STT로 변환하고, 현재 선택된 GLM/Codex/Grok 대화 엔진으로 대화 유형을 분류·요약해 같은 방에 전달하는 개발 범위를 고정하기 위한 작업 문서다.

## 개발 목적

카카오톡의 MP3·M4A 음성 파일과 실제 PD20에서 확인된 WAV 첨부를 안전하게 식별하고, `proxy-manager → proxy-audio`에서 한국어 STT를 수행한다. STT 결과는 원문 증거로 보존하고, Android가 현재 대화 엔진 설정을 snapshot하여 자동 또는 사용자 지정 형식으로 요약한다.

기존 원칙을 유지한다.

- 기본 대화 엔진 GLM은 Android의 `GlmClient`가 직접 호출한다.
- Codex/Grok은 기존 `proxy-conversation` 경로를 사용한다.
- PD20은 서버에서 `proxy-manager:4340`만 호출한다.
- 음성 분석 장애는 텍스트·일반대화·이미지·영상·펜브러쉬 기능을 중단시키지 않는다.

## 사전 실기기·호스트 확인 결과

2026-08-04 1차 확인은 운영 앱이나 카카오 DB를 변경하지 않는 read-only probe로 진행했다. 이어 사용자 요청에 따라 Chromium 공개 M4A fixture를 검증·전송하고, R01에 생성된 단일 발신 행만 read-only로 복호화해 실제 계약을 확인했다. 서명 URL 원문·사용자 ID·오디오 bytes는 출력하거나 host로 복사하지 않았다. 전송·DB probe APK와 PD20 임시 파일은 확인 직후 삭제했고 임시 소스도 작업 트리에서 제거했다.

### 사전 확인 결론

1. type `18`만 보고 STT를 시작하면 ZIP·PDF까지 오디오로 오인하므로 **확장자 1차 필터와 서버 magic/ffprobe 2차 검증이 모두 필요**하다.
2. 사용자가 요청한 MP3와 WAV는 기존 PD20 DB에서 확인했고, M4A도 테스트 fixture를 R01에 실제 전송해 동일한 type `18`·attachment key 계약을 확인했다.
3. KakaoTalk에서 실제 WAV가 확인됐으므로 MVP 지원 포맷을 MP3·M4A·WAV로 고정한다.
4. attachment에 MIME·duration이 없으므로 filename, Content-Type, Content-Length를 신뢰하지 않고 실제 bytes와 ffprobe를 기준으로 판정한다.
5. 현재 `GlmAutoReplyHandler.isCandidate()`는 type `1`만 처리하므로 type `18`은 일반대화로 잘못 응답하지 않는다. 신규 `AudioAnalysisCoordinator`가 독립 처리해야 한다.
6. 현재 `proxy-conversation`과 Codex/Grok internal conversation은 message당 4,000자 제한이 있어 긴 transcript를 그대로 전달할 수 없다. audio 전용 chunk·summary 계약이 필요하다.
7. 현재 Kakao 답변은 480자로 잘리므로 요약/원문을 위한 순서 보장 multipart delivery가 필수다.
8. 현재 host에는 STT runtime/model이 없으므로 이번 사전 시험은 **M4A 실제 Kakao 전송·DB attachment 식별·복호화 계약까지만 PASS**다. fixture가 440 Hz tone이라 STT 정확도 시험에는 사용하지 않으며, 실제 한국어 STT 정확도·속도는 Phase 0 model canary에서 별도로 판정한다.

|---|---|
| STT engine | Apple Silicon 운영 적합성을 우선해 `whisper.cpp`를 primary로 사용한다. 버전·model SHA-256을 pin한다. |
| 최초 model | `large-v3-turbo`를 후보로 두고 `large-v3`와 한국어 fixture CER/RTF를 비교한 뒤 하나를 확정한다. |

| 정규화 | `ffmpeg` 고정 argv로 mono, 16 kHz, PCM s16le WAV를 만든다. 사용자 argv·path는 받지 않는다. |
| STT 언어 | 기본 `ko` 고정. 한국어 안의 영어 고유명사는 원문 유지하고 자동 번역하지 않는다. |
| 대화 엔진 | job 시작 시 Android의 현재 GLM/Codex/Grok mode와 promptVersion을 snapshot한다. 도중 mode 변경은 진행 중 job을 바꾸지 않는다. |
| GLM 경로 | 기존 독립 구조대로 Android `GlmClient`를 사용한다. |
| Codex/Grok 경로 | `proxy-conversation`에 audio-summary 전용 versioned contract를 추가하되 일반대화 4,000자 계약은 변경하지 않는다. |
| summary 구조 | `pattern`과 `view`를 독립 축으로 둔다. 자동 분류 신뢰도가 낮으면 `GENERAL`로 fallback한다. |
| 근거 | 결정·액션·날짜·금액·인용 요지는 모두 transcript segment ID와 timestamp를 내부 근거로 가진다. |
| 화자 | MVP는 speaker identity를 만들지 않는다. 화자 구분이 없으면 담당자·발언자를 추측하지 않는다. |
| 자동 분석 | 별도 `AUDIO_AUTO_ANALYSIS`, deny-by-default. `AUDIO_ANALYSIS`와 `TEXT`가 모두 ON일 때만 켤 수 있다. |
| 최근 대상 | 같은 방의 누구나 올린 음성을 다른 참여자가 요청할 수 있다. 답장 없는 수동 명령은 같은 `chatId`의 최근 30분 최신 지원 오디오를 선택하고, exact reply는 CDN 만료와 방 일치 여부를 기준으로 DB fallback한다. 작업 제어는 요청 사용자별로 분리한다. |
| 입력 한도 | 운영 기본 100 MiB·120분, per-room 1개·global 2개. 실제 benchmark와 Kakao 제한을 확인해 더 낮출 수는 있지만 자동 확대하지 않는다. |
| 재요약 | STT와 summary identity를 분리해 엔진·pattern·view 변경 시 transcription을 다시 실행하지 않는다. |
| 엔진 snapshot | 최초 summary 시작 시 현재 mode를 고정한다. `재요약`은 재요약 시작 시점의 새 mode를 snapshot한다. |
| raw audio | download/normalization/STT가 끝나면 즉시 삭제하고 terminal cleanup에서도 재삭제한다. |
| transcript | root-only 암호화 저장, 기본 24시간 TTL, 최대 7일 설정 한도. `헤이봇 음성 삭제`로 즉시 purge한다. |
| source URL | download가 시작되면 job DB에서 제거하고 로그·trace·응답에 절대 남기지 않는다. |
| 실패 격리 | STT 성공·요약 실패 상태를 보존해 `재요약`만 가능하게 한다. 음성 장애는 기존 기능 circuit을 trip하지 않는다. |

```text
헤이봇 음성 요약
헤이봇 음성 요약 자동 기본
헤이봇 음성 요약 회의 회의록
헤이봇 음성 요약 회의 액션
헤이봇 음성 요약 강의 상세
헤이봇 음성 상태
헤이봇 음성 취소
헤이봇 음성 재요약
헤이봇 음성 원문 [페이지]
헤이봇 음성 근거 [페이지]
헤이봇 음성 삭제
```

관리자는 코어라인 AI 연구소에서만 다음 순서로 방 정책을 바꾼다.

```text
헤이봇 음성 허용 R01
헤이봇 방 적용 <확인코드>

헤이봇 음성자동 허용 R01
헤이봇 방 적용 <확인코드>

헤이봇 음성자동 불허용 R01
헤이봇 방 적용 <확인코드>
```

- `음성 요약`의 기본값은 `자동 기본`이다.
- 명령 대상은 같은 방의 exact reply → 같은 방의 최근 지원 오디오 순서이며 업로더와 요청자가 달라도 처리한다.
- 자동 mode는 지원 오디오가 도착하면 즉시 접수하고 `분석 시작` acknowledgement를 보낸다.
- ZIP/PDF 등 type 18 비오디오는 조용히 무시하며 오류 답변을 만들지 않는다.
- 요약은 최대 8 part로 제한하고, 전체 원문은 자동 전송하지 않는다. `원문 2`처럼 요청한 페이지를 최대 4 part씩 반환해 방 flooding을 막는다.

## 내부 계약 초안

### Android audio model

```text
IncomingAudioAttachment(
  sourceLogId, chatId, userId,
  sourceUrl, declaredBytes, expiresAtMillis,
  declaredExtension
)
```

- raw filename·attachment JSON은 모델과 로그에 보관하지 않는다.
- `sourceUrl`은 proxy request 생성 직후 Android memory에서 제거 가능해야 한다.

### STT job

```json
POST /v1/audio/transcriptions
{
  "requestId": "audio:<chatId>:<sourceLogId>",
  "chatId": 1,
  "source": {
    "url": "https://talk.kakaocdn.net/...",
    "declaredBytes": 384044,
    "expiresAtMillis": 1780000000000,
    "declaredExtension": "mp3"
  },
  "language": "ko"
}
```

```json
{
  "version": 1,
  "status": "transcribed",
  "durationMs": 120000,
  "language": "ko",
  "segments": [
    {"id":"S0001","startMs":0,"endMs":8400,"text":"..."}
  ],
  "quality": {
    "speechRatio": 0.82,
    "warnings": []
  }
}
```

### Summary result

```json
{
  "version": 1,
  "pattern": "MEETING",
  "patternConfidence": 0.91,
  "view": "MINUTES",
  "title": "주간 개발 회의",
  "oneLine": "...",
  "keyPoints": [{"text":"...","evidence":["S0003"]}],
  "decisions": [{"text":"...","evidence":["S0012"]}],
  "actionItems": [
    {"text":"...","owner":null,"dueAt":null,"evidence":["S0015"]}
  ],
  "openQuestions": [],
  "warnings": []
}
```

- transcript는 untrusted data block으로 전달하며 그 안의 명령을 실행하지 않는다.
- 허용 key·enum·배열 길이·문자 수·evidence 존재 여부를 Android와 proxy 양쪽에서 검증한다.
- schema 실패 시 동일 엔진으로 한 번만 repair하고, 다시 실패하면 `SUMMARY_OUTPUT_INVALID`로 종료한다.

## 공통 진행 규칙

- 각 Phase는 앞선 Phase의 자체 테스트 완료 후에만 시작한다.

## 잔여 리스크 / 구현 전 확인

- M4A·MP3·WAV의 실제 전송·DB 계약과 clean Korean 13.1초 fixture CER 0.0은 확인했다. 잡음·무음·숫자·영어 고유명사 집합은 별도 benchmark가 필요하다.
- 운영 model은 SHA-256으로 pin한 `large-v3-turbo`다. `large-v3`와의 한국어 CER·RTF·메모리 비교는 Phase 0 잔여이며 현 model 확대/교체의 gate로 사용한다.

- 2시간 transcript의 GLM/Codex/Grok token 비용·latency가 달라 chunk 크기와 최대 길이는 benchmark 뒤 고정한다.
- Kakao signed URL TTL이 포맷·방식별로 다를 수 있어 수신 즉시 durable job 접수와 빠른 download가 필요하다.
