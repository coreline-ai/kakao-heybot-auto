# implement_20260725_210700.md

작성 일시: `2026-07-25 21:07:00 KST`

이 문서는 old-bot의 검증된 펜 선화·브러시 채색 엔진을 헤이봇에 **별도 드로우 영상 기능**으로 적용하기 위한 개발 범위를 고정한다. 기존 Grok 영상 기능과 실행 경계·작업 큐·권한을 공유하지 않으며, 모든 외부 생성과 실기기 전송은 기본 OFF 상태에서 단계적으로 검증한다.

## 개발 목적

허용된 카카오톡 방에서 사용자가 `헤이봇 펜브러쉬 <설명>`을 입력하면, 헤이봇이 제어된 일러스트 원본을 생성하고 다음 순서로 검증된 10초 세로 MP4를 원래 방에 native 전송한다.

```text
원본 일러스트 생성 → 펜 외곽선 드로잉 → 펜 종료 → 브러시 색상 채색 → QA → Kakao MP4 전송
```

## 개발 범위

- old-bot의 `pen-brush-video` 엔진 중 선화/색상 분리, route 생성, Remotion 2단계 렌더링, QA만 versioned vendor snapshot으로 이식
- `proxy-draw`(domain)와 `proxy-brush`(internal render engine)를 별도 프로세스로 구성
- `proxy-codex`의 제한된 이미지 생성 capability를 `draw` caller가 사용할 수 있도록 확장하고, 펜브러쉬 전용 원본 프롬프트를 `proxy-draw`가 통제
- `proxy-manager`의 기본 OFF `/v1/draw` route, launchd/watchdog, health/readiness 연결
- Iris의 전용 명령·작업 상태·취소·재전송·native video delivery 연동
- control room 관리자만 변경 가능한 `PEN_BRUSH` room capability와 기존 preview → apply 흐름
- 작업별 SQLite 상태, 방/사용자 scope, idempotency, 취소, artifact retention, MP4/프레임 QA
- 고정 fixture 기반 자동 검증과 별도 승인된 비공개 방 E2E

## 제외 범위

```text
new-bot/vendor/server/proxy-brush/engine/       # old-bot에서 고정한 renderer snapshot
new-bot/vendor/server/proxy-brush/             # internal: fixed pen-brush render capability
new-bot/vendor/server/proxy-draw/              # gateway: draw job, scope, source, QA, artifact
```

| 단위 | 책임 | 금지 책임 |
|---|---|---|
| `proxy-manager` | route 인증, registry, health, binary relay | draw job·이미지 생성·렌더링 소유 |
| `proxy-draw` | chat scope, idempotency, queue, 제어된 source request, final MP4/retention | 임의 process 실행, Kakao 직접 전송 |
| `proxy-codex` | caller allowlist 안의 `image.generate` 원본 PNG artifact | 방/사용자 권한, draw render 실행 |
| `proxy-brush` | 고정 pen-brush render, workspace/process 격리, route/QA report | user prompt 해석, room scope, 공개 게시 |
| Iris | exact command parse, local capability 재확인, polling, native delivery 확인 | Codex/renderer 직접 실행, secret·workspace 접근 |

## 공통 진행 규칙

- 각 Phase는 앞선 Phase의 자체 테스트와 완료 조건을 통과한 뒤에만 시작한다.
- 2026-07-25 기준 엔진 snapshot·로컬 renderer·Iris command까지 구현했고, 고정 source PNG로 `proxy-brush`의 실제 10초 렌더를 통과했다. Codex 원본 생성과 실제 카카오 전송은 기본 OFF이며 아직 실행하지 않았다.
- 모든 listener는 `127.0.0.1`만 bind한다. Iris는 기존 manager 단일 ingress만 ADB reverse/LAN 보안 경로로 호출한다.
- proxy 간 credential은 역할별 private secret file로 분리한다. secret, 원문 prompt, artifact local path, raw child output은 상태 응답·카카오 메시지·일반 로그에 남기지 않는다.
- 모든 `chatId`, `userId`, `logId`는 decimal string으로 HTTP/SQLite 경계를 통과한다. 상태·file·취소는 항상 `jobId + chatId`를 함께 검증한다.
- `proxy-brush`는 `pen-brush-video` 고정 capability만 제공한다. 외부 입력으로 profile, Python command, Node command, output path, project YAML을 바꿀 수 없다.
- job workspace와 artifact directory는 job별로 분리하고, regular-file/realpath/size/extension 검증을 통과한 파일만 다음 단계로 전달한다.
- cancel/timeout은 renderer child process group을 종료하고, 완료 후 capability revision이 바뀌었으면 stale artifact를 카카오에 전송하지 않는다.
- 구현 중 발견한 이슈는 해당 Phase에 기록하고 수정한다. 계획 밖 기능은 별도 계획으로 분리한다.
