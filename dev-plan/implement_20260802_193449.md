# implement_20260802_193449.md

작성 일시: `2026-08-02 19:34:49 KST`

이 문서는 PD20이 USB 장치로는 연결되어 있지만 Mac ADB daemon이 해당
transport를 잃어 `adb reverse tcp:4340`이 끊기고, 이미지 분석 요청이
`ConnectException`으로 실패한 장애의 재발을 막기 위한 개발 범위를 고정한다.

## 개발 목적

PD20과 Mac 프록시 플랫폼 사이의 연결을 단순한 USB 물리 연결 여부가 아니라
**ADB transport, reverse mapping, PD20 loopback readiness**까지 검증한다. 연결이
일시적으로 끊기면 watchdog이 ADB transport와 reverse를 자동 복구하고, 이미지
분석 요청은 복구 시간 동안 같은 request ID로 제한 재시도하여 사용자에게 즉시
실패 메시지가 노출되지 않게 한다.

USB ADB를 우선 사용하되, 사용자가 미리 승인·페어링한 Android Wireless
Debugging이 있으면 USB 장애 때 TLS 무선 ADB reverse로 제한적으로 전환한다.

## 개발 범위

- PD20 USB 물리 장치와 ADB 논리 transport 상태의 분리 판정
- ADB `offline`·transport 누락의 단계적 자동 복구
- 반복적인 ADB daemon 재시작을 막는 threshold·cooldown·실행 잠금
- `adb reverse tcp:4340 tcp:4340`의 멱등 복원
- PD20 내부에서 manager `/ready`를 호출하는 실제 종단 간 연결 확인
- 이미 페어링된 TLS Wireless Debugging endpoint 탐색·검증·USB 우선 failover
- Vision job create의 transport 오류 제한 재시도와 오류 분류
- provider 실패 원인이 reply `DB_CONFIRMED`로 사라지지 않는 trace 보존
- launchd·fake-ADB·Android unit test·PD20 장애 주입 E2E
- 운영 문서와 개발계획 인덱스 갱신

## 제외 범위

- `proxy-manager`의 `0.0.0.0` 또는 LAN interface bind
- 공개 인터넷, tunnel, port forwarding을 통한 프록시 공개
- legacy `adb tcpip 5555` 자동 활성화
- Wireless Debugging 자동 pairing 또는 사용자 승인 우회

- PD20 이외 기기의 임의 제어·배포·재기동
- 연결 장애를 이유로 GLM·카카오 DB observer·전체 앱을 재시작하는 처리

## 장애 기준선

2026-08-02 실제 장애에서 다음을 확인했다.

| 계층 | 관측 결과 |
|---|---|
| macOS USB | `ioreg`에서 PD20과 serial `0123456789ABCDEF`가 정상 인식됨 |
| ADB | 같은 시점 `adb devices -l`에는 Samsung만 있고 PD20은 누락됨 |
| host manager | `127.0.0.1:4340/health`, `/ready` 모두 `200` |
| proxy-vision | `127.0.0.1:4362/ready`에서 Codex dependency 포함 `ready=true` |
| PD20 Iris | `Vision job create failed: ConnectException` 기록 |
| Vision store | 실패 시점의 신규 job이 없으므로 요청이 host까지 도달하지 않음 |
| 수동 복구 | host ADB daemon 재시작 뒤 PD20 재인식, reverse 복원, PD20 `/ready` `200` |

현재 watchdog의 `ensure_adb_reverse`는 `adb get-state`가 `device`가 아니면
아무 조치 없이 반환한다. 따라서 **USB는 보이지만 ADB transport가 누락된 상태**를
복구하지 못한다.

추가로 현재 `test-watchdog.sh`는 실제 restart label 9개와 달리 7개를 기대해
`expected=7 actual=9`로 실패한다. 구현 첫 단계에서 이 기준선부터 정정한다.

## 결정된 구현 정책

| 항목 | 결정 |
|---|---|
| 고정 기기 식별자 | `0123456789ABCDEF` |
| manager 주소 | `127.0.0.1:4340` 유지 |
| watchdog 실행 간격 | 10초 |
| transport 누락 threshold | 연속 2회 |
| ADB daemon restart cooldown | 300초 |
| 복구 우선순위 | USB device → ADB reconnect → ADB daemon restart → paired wireless ADB |
| reverse 복구 | target transport가 `device`일 때 즉시 멱등 적용 |
| 종단 확인 | PD20 `/system/bin/curl`로 manager `/ready` 확인 |
| 무선 경로 | 이미 페어링된 `_adb-tls-connect._tcp`만 opt-in 사용 |
| USB 복귀 | USB serial이 다시 `device`이면 다음 주기에 USB 우선 복귀 |
| Vision 재시도 | 동일 request ID, 2초·5초·10초 지연 후 최대 3회 추가 시도 |
| 재시도 대상 | `ConnectException`·transport 계열 timeout만 허용 |
| 재시도 금지 | 4xx, 인증 실패, invalid response, policy·rate-limit 실패 |
| 상태 파일 | root 사용자 전용 또는 현재 launchd 사용자 전용 atomic file, mode `600` |

## 복구 상태 흐름

```text
host manager health/ready 확인
  ├─ 실패: 기존 proxy readiness 복구 경로
  └─ 성공
      └─ USB serial의 ADB state 확인
          ├─ device: reverse 확인·복원
          ├─ offline: adb reconnect 후 재확인
          └─ absent
              ├─ USB 물리 장치 존재 + 2회 연속 누락
              │   └─ cooldown 확인 후 ADB daemon 재시작
              └─ USB transport 복구 실패
                  └─ opt-in paired wireless endpoint 탐색·serial 검증

선택된 ADB target
  └─ reverse tcp:4340 적용
      └─ PD20에서 http://127.0.0.1:4340/ready 확인
          ├─ 200: READY
          └─ 실패: reverse 재생성 1회 후 DEGRADED
```

- ADB daemon 재시작은 물리 PD20 존재와 threshold·cooldown을 모두 충족할 때만 허용한다.

- pairing·`adb tcpip 5555`·LAN bind는 구현하지 않는다.
