## 개발 목적

일반대화가 답변을 보낸 뒤에도 다음 발화에서 앞선 질문·답변을 모르는 문제를 해결한다. 기존의 `(chatId, userId)` 기반 영속 대화 기억을 공통 문맥으로 사용해, 호출어 대화와 일반대화가 안전하게 이어지도록 한다.

## 개발 범위

- 문맥 key를 정확한 `(chatId, userId)`로 고정한다.
- 호출어 대화와 일반대화의 **성공 전송된** user/assistant turn을 기존 `ConversationMemoryStore`에 함께 저장한다.
- 일반대화 arbitration 요청에 해당 사용자·해당 방의 최근 4턴/30분 문맥만 넣는다.
- `WAIT`로 판정된 미완성 발화는 메모리에 영속화하지 않고, 같은 key에만 최대 2개·2분 동안 임시 보관해 다음 일반대화 판정에만 사용한다.
- `REPLY`의 카카오 전송 성공 뒤에만 일반대화 turn을 commit한다. 전송 실패·안전 차단·모델 실패·`IGNORE`·invalid 결과는 assistant turn으로 저장하지 않는다.
- 일반대화 시작·종료·회로 차단·기억 초기화 때 임시 미완성 발화를 삭제한다.
- 단위/회귀 테스트, release build, PD20 배포 및 무해한 상태 점검을 수행한다.

## 제외 범위

## 결정 기록

| 항목 | 결정 |
|---|---|
| 기본 문맥 | 사용자별. 같은 `chatId`와 `userId`가 모두 일치할 때만 이전 turn을 사용한다. |
| 호출어와 일반대화 | 같은 `ConversationMemoryStore`를 공유한다. 따라서 두 경로를 오가도 같은 사용자의 앞선 성공 대화를 이해한다. |
| 일반대화 저장 시점 | strict `REPLY` → safety 통과 → 카카오 전송 성공 뒤에만 저장한다. |
| 미완성 발화 | `WAIT`일 때만 process-memory에 최대 2개·2분 둔다. 재시작·종료·회로 차단 뒤에는 남지 않는다. |
| 방 전체 공유 | 이번 범위에서 만들지 않는다. 타인의 발화가 섞이는 공개방 오답 위험을 피한다. |
| 보관 | 기존 설정값인 최근 4턴·30분 TTL과 root 전용 원자 저장을 그대로 사용한다. |
