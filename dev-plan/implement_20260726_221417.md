# implement_20260726_221417.md

작성 일시: `2026-07-26 22:14:17 KST`

이 문서는 일반대화 ON/OFF 상태를 재배포·프로세스 재시작 뒤에도 안전하게 복원하는 개발 범위를 고정하고, 구현이 목적 밖으로 확장되지 않도록 하기 위한 작업 문서다.

## 개발 목적

현재 `GeneralConversationModeStore`는 `enabled=false`인 process-local 변수만 사용한다. PD20 APK 배포 스크립트가 기존 `app_process`를 종료하고 새 프로세스를 시작할 때 관리자가 켠 일반대화 상태가 항상 사라진다.

관리자의 명시적 시작·종료 상태를 root 전용 원자 파일에 저장하고 재시작 때 복원한다. 안전회로에 의한 자동 정지는 반드시 OFF로 저장해 프로세스 재시작이 안전정지를 우회하지 못하게 한다.

## 개발 범위

- 일반대화 mode 전용 versioned JSON 상태 파일과 원자적 읽기·쓰기
- 관리자 `대화 시작/종료` 및 circuit trip의 영속 상태 변경
- 프로세스 시작 시 저장 상태 복원, 누락·손상·권한 오류 시 기본 OFF
- `close()`는 현재 프로세스의 in-flight 작업만 무효화하고 저장된 운영 상태는 변경하지 않는 lifecycle 분리
- PD20 배포 스크립트의 mode 파일 metadata 검사와 환경변수 전달
- 관리자 상태 출력과 시작 로그의 원문 없는 복원·저장 상태 표시
- JVM 회귀 테스트, 실제 release build, PD20 재배포·재시작 복원 검증
- 기존 일반대화 토큰 잘림 방지와 자동 재시도 회귀 유지

| 항목 | 결정 |
|---|---|
| 상태 파일 | `/data/local/private/iris-general-conversation-mode.json`, `600 root:root` |
| 저장 내용 | schema version, `enabled`, 갱신 시각만 저장한다. chatId·userId·대화 원문은 저장하지 않는다. |
| 최초 기동 | 파일 누락 시 OFF로 시작한다. 관리자가 한 번 `헤이봇 대화 시작`을 실행해야 한다. |
| 관리자 시작 | ON 저장 성공 후에만 runtime ON으로 전환한다. 저장 실패 시 OFF를 유지한다. |
| 관리자 종료 | runtime을 즉시 OFF로 만들고 OFF를 저장한다. 저장 실패 시 기존 ON 파일을 quarantine해 다음 시작도 fail-closed 처리한다. |
| circuit trip | 관리자 종료와 같은 영속 OFF 경로를 사용한다. 재시작으로 자동 복구하지 않는다. |
| process close | runtime epoch만 무효화한다. 저장된 ON/OFF 운영 의도는 바꾸지 않는다. |
| 손상 파일 | 원문 없이 generic 로그를 남기고 quarantine한 뒤 OFF로 시작한다. |
