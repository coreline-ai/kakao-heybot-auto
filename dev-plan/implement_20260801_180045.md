# implement_20260801_180045.md

작성 일시: `2026-08-01 18:00:45 KST`

이 문서는 카카오 오픈채팅에 올라온 이미지를 PD20의 KakaoTalk DB에서 식별하고, 검증된 이미지 원본을 Vision 분석한 뒤 같은 방에 설명하는 기능의 범위를 고정하기 위한 작업 문서다.

## 개발 목적

현재 `ObserverHelper`는 `chat_logs.attachment`를 복호화하지만 이미지 첨부정보를 기능 도메인으로 전달하지 않는다. 이미지 생성 기능과 분리된 이미지 분석 경로를 추가해, 사용자가 이미지 전송 후 `헤이봇 이미지 분석`을 입력하면 같은 방·같은 사용자의 최근 이미지를 분석하고 짧은 설명을 응답하게 한다.

실기기 사전 확인에서 코어라인 AI 연구소의 이미지 행, attachment 복호화, Kakao CDN 원본 다운로드와 PNG 검증까지 성공했으므로 구현 가능성은 확인된 상태다.

## 개발 범위

- PD20 `chat_logs` 이미지 행과 복호화된 attachment를 안전한 도메인 모델로 변환
- 같은 `(chatId,userId)`의 최근 이미지 참조를 설정 가능한 선택 시간 동안 메모리에 유지
- 정확한 답장 참조 또는 앱 재시작 후 최근 이미지 선택 시 `chat_logs` DB를 읽는 fallback 제공
- `헤이봇 이미지 분석` 명령으로 최근 이미지 분석 실행
- 별도 `IMAGE_ANALYSIS` 방 capability와 중앙 관리자 preview/apply 제어
- `proxy-manager → proxy-vision → proxy-codex`의 비동기 Vision 분석 경로
- Kakao CDN URL·만료·호스트·크기·MIME·매직바이트 검증
- 분석 결과 JSON 계약, 응답 sanitizer, 같은 방·스레드 답장
- Android·Node 자동 테스트, PD20 release 배포, 코어라인 AI 연구소 제한 E2E

## 제외 범위

- 허용방의 모든 이미지를 자동으로 분석·답장하는 기능
- 이미지 생성용 `IMAGE` capability와 기존 `proxy-image`의 책임 변경
- 방 전체에서 다른 사용자의 최근 이미지를 임의로 선택하는 기능
- 앨범 전체·동영상·GIF·파일 첨부 분석
- 얼굴 신원 확인, 민감 속성 추론, 의료·법률 판정
- Kakao CDN 외 임의 URL 다운로드
- 이미지 원본·서명 URL·Base64·OCR 원문 장기 저장 또는 로그 출력
- GLM/Grok Vision provider 동시 도입; 최초 구현은 Codex Vision 경로만 사용

## 결정 기록

| 항목 | 결정 |
|---|---|
| 최초 트리거 | 이미지 전송 후 `헤이봇 이미지 분석` 명령을 명시적으로 실행한다. |
| 대상 선택 | 답장 `src_logId/threadId`가 있으면 같은 방의 해당 이미지 로그를 정확히 선택한다. 없으면 동일 `(chatId,userId)` 최신 이미지를 우선하고, 없을 때만 같은 방의 최신 헤이봇 발신 이미지 1개를 선택한다. |
| 선택 시간 | 동일 사용자 fallback은 `IRIS_VISION_RECENT_IMAGE_WINDOW_MS`를 적용하며 운영 기본값은 30분이다. 정확한 답장과 최신 헤이봇 이미지 fallback은 임의 시간 제한 대신 CDN 실제 만료를 기준으로 한다. |
| DB fallback | 메모리 cache miss·앱 재시작 시 정확한 답장은 `(chatId,sourceLogId)`, 최근 이미지는 `(chatId,userId)`로 `chat_logs`를 조회하고 attachment를 다시 복호화·검증한다. |
| 다른 사용자 이미지 | 직접 답장 참조가 없는 한 선택하지 않는다. |
| 봇 자체 이미지 | 자동 분석은 하지 않는다. 정확한 답장 또는 같은 봇 계정에서 보낸 명시적 `헤이봇 이미지 분석` 명령의 동일 사용자 최근 fallback으로만 분석한다. |
| 방 정책 | `RoomCapability.IMAGE_ANALYSIS`를 `IMAGE`와 독립 추가하고 기본 불허용으로 migration한다. |
| 외부 경로 | PD20은 기존 manager `4340`만 사용하고 `/v1/vision`으로 요청한다. |
| Domain proxy | 신규 `proxy-vision`, loopback `4362`, manager gateway, dependency `codex`로 분리한다. |
| Engine capability | `proxy-codex`에 caller `vision` 전용 `image.analyze.v1`만 추가한다. 자유 CLI/argv는 노출하지 않는다. |
| 원본 전달 | PD20은 attachment의 Kakao CDN URL과 검증 metadata만 전송한다. `proxy-vision`이 엄격한 allowlist로 원본을 가져온다. |
| Job 모델 | `requestId=vision:<chatId>:<imageLogId>`의 비동기 durable job과 chatId scope를 사용한다. |
| 응답 | 2~4문장 한국어 설명, 눈에 보이는 사실 중심. 불확실한 추측과 신원·민감 속성 판단은 금지한다. |

## API 계약 초안

PD20 → manager → `proxy-vision`:

```json
POST /v1/vision/jobs
{
  "requestId": "vision:<chatId>:<imageLogId>",
  "chatId": 1,
  "source": {
    "url": "https://talk.kakaocdn.net/...",
    "width": 1254,
    "height": 1254,
    "declaredBytes": 1591685,
    "expiresAtMillis": 1786783922282
  },
  "question": "이 이미지가 무엇인지 설명해줘"
}
```

분석 결과 내부 계약:

```json
{
  "version": 1,
  "summary": "밝은 연구실에서 흰색 로봇이 손을 흔들고 있습니다.",
  "visibleObjects": ["로봇", "책상", "화분", "연필꽂이", "모니터"],
  "visibleText": [],
  "uncertainty": "low"
}
```

응답 JSON은 strict key·길이 검증 후 기존 개인정보 sanitizer를 통과해야 한다.

## Phase 1A. 답장 참조·최근 이미지·DB fallback 분리 수정

### 목표

최초 구현의 메모리 2분 일괄 만료를 제거하고, 정확한 답장 참조와 답장 없는 최근 이미지 선택을 서로 다른 규칙으로 처리한다.

### 구현 태스크

- [x] cache API를 같은 방 exact logId 조회와 같은 사용자 최근 조회로 분리한다.
- [x] 정확한 답장 cache miss는 `(chatId,sourceLogId)` DB 조회로 복구하고 임의의 2분 제한을 적용하지 않는다.
- [x] 답장 없는 cache miss는 `(chatId,userId)` DB 조회로 복구하고 설정 가능한 최근 선택 시간만 적용한다.
