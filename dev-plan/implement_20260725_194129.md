이 문서는 **인증된 공식 Grok CLI OAuth 세션**을 이용한 비디오 생성을 헤이봇 프록시
플랫폼에 안전하게 추가하기 전의 개발 계획이다. `proxy-video`·`proxy-grok`은 이미
CLI 경계가 예약되어 있다. 아래 Phase 0에서 실제 CLI의 비디오 명령·산출물 계약을
검증하기 전에는 유료 생성, secret 배치, registry enable을 하지 않는다.

> 정정 기록: 초안의 “xAI Video REST API adapter” 결정은 채택하지 않는다. 이 기능의
> provider 경계는 `proxy-grok -> 인증된 Grok CLI`다. REST API·API key는 fallback도
> 포함해 구현하지 않는다.

## 최신 CLI 실검증 기록 — 2026-07-25

운영자의 명시 승인 아래 로그인된 공식 Grok Build CLI에서 분홍 로봇이 손을 흔드는
비디오를 시험했다. 3번째 시도는 headless CLI에서 성공했다.

| 검증 항목 | 결과 |
|---|---|
| CLI/OAuth | `grok 0.2.111 stable`, `grok.com` 로그인 상태 확인 |
| CLI 진입점 | Grok Build **TUI slash command** `/imagine-video`와 headless `grok -p`가 Imagine의 `image_to_video`를 호출하는 것을 확인. 3번째 headless 시도에서 성공 JSON·세션 상대 artifact link `videos/1.mp4`를 반환 |
| 3초 직접 생성 | 불가. 설치된 Imagine skill의 video duration은 `6s` 또는 `10s`만 지원한다고 응답 |
| 이전 실패 | 첫 2회는 ZDR의 `output.upload_url` 요구 HTTP 400으로 실패 |
| 성공 산출물 | 로컬 CLI session runtime에 MP4 생성 확인. `6.041667초`, `544×544`, `24fps`, H.264 primary video, AAC stream, 약 `633KB` |
| 비용 관찰 | 성공 CLI는 Grok Build model turn 비용 약 `$0.0425`을 보고했다. video artifact/출력 사용량은 별도로 보고되지 않았다. |

ZDR 오류는 같은 OAuth CLI에서 뒤이은 headless 시도 성공으로 해소됐지만, 원인은 아직
확정하지 않았다. 따라서 `VIDEO_ZDR_UPLOAD_URL_REQUIRED`는 영구 blocker가 아니라
**단일 제한 재시도 뒤 circuit-open으로 전환하는 provider 오류**로 취급한다. API key,
REST, 웹 자동화로 우회하지 않는다.

성공 artifact는 current CLI session runtime의 `videos/1.mp4` 형태로 확인됐다. 이 경로를
`$HOME` 기반 문자열로 하드코딩하지 않는다. adapter가 CLI가 반환한 session/artifact
reference를 사용해 허용된 session root 안에서만 `realpath`로 탐색할 수 있는지 다음
Phase 0 계약 검증에서 확인한다.

3초는 provider 직접 duration이 아니다. 6초 생성 뒤 로컬에서 처음 3초만 자르는 방식은
가능한 후보지만, 최소 6초 사용량이 발생하고 별도 media 처리 범위가 추가된다. 성공한
6초 artifact가 확인됐으므로, 3초 product option 채택은 비용·AAC 처리·ffmpeg QC 기준을
별도 결정한 뒤에만 진행한다.

## 2026-07-25 구현 반영 기록

- Android Iris에 **정확한 생성 trigger `헤이봇 영상 <설명>`**과 `영상 상태`·`영상 취소`·`영상 재전송`을 추가했다. 호출어가 문장 중간에 있는 일반 대화는 영상 명령으로 오인하지 않는다.

- `proxy-video`은 SQLite job/room scope/idempotency, queue 전체 2·방당 1, MP4 signature 및 `ffprobe` H.264/duration/resolution QC를 구현했다.
- 2026-07-26 사용자 요청으로 `video`/`grok` registry, launchd, ADB reverse, Android `IRIS_VIDEO_PROXY_ENABLED=true`를 배포했다. 코어라인 AI 연구소(R01)만 VIDEO 허용이며, 실제 첫 Kakao native delivery와 비용·사용량 관측은 남아 있다.
- 자동 검증: `proxy-grok`·`proxy-video` TypeScript build/unit test, Iris video router/capability/coordinator unit test 통과. 실제 launchd·ADB·Kakao E2E는 미실행이다.

## 예상 책임 경계

```text
PD20 Iris
  -> proxy-manager (/v1/video, route secret)
  -> proxy-video (video job·room scope·MP4 QC·retention)
  -> proxy-grok (CLI profile·doctor·고정 capability adapter·raw artifact)
  -> authenticated official Grok CLI
  -> xAI OAuth session
```

| 단위 | 책임 | 금지 책임 |
|---|---|---|
| `proxy-manager` | route auth, registry, health, binary relay | video job·OAuth profile·media QC 소유 |
| `proxy-video` | user job, exact room scope, domain queue, MP4 QC, final artifact | CLI credential·임의 CLI 실행 |
| `proxy-grok` | CLI path/version/OAuth readiness, fixed video command, child lifecycle, raw artifact confinement | Kakao room·명령·범용 shell/API key/REST 호출 |
| Iris | command parse, local policy, status polling, Kakao native video delivery | OAuth credential·직접 CLI/HTTP provider 호출 |

## 공통 진행 규칙

- 각 Phase는 앞선 Phase의 자체 테스트와 decision gate를 통과한 뒤에만 시작한다.
- CLI OAuth credential과 profile은 `proxy-grok` 전용 권한으로만 접근한다. route/admin/image secret을 재사용하지 않는다.
- proxy 간 shared secret은 root-only file로 주입하고 constant-time 비교한다. env dump·health·error·metric에는 secret/profile path/CLI argv를 노출하지 않는다.
- 모든 listener는 `127.0.0.1`만 bind한다. OAuth profile·workspace·artifact runtime directory 권한은 소유 계정만 읽고 쓴다.
- child process에는 최소 환경만 전달한다. credential discovery에 필수인 변수·directory는 Phase 0에서 확인한 것만 allowlist에 넣는다.
- stdout/stderr·입력·artifact 수·artifact bytes를 각각 상한으로 제한한다. timeout/cancel은 child **process group**에 `SIGTERM` 후 짧은 grace를 거쳐 `SIGKILL`한다.
- 모든 `chatId`·`userId`·`logId`는 decimal string으로 HTTP·SQLite 경계를 통과한다. JavaScript number를 쓰지 않는다.
- status/file/cancel은 항상 `jobId + chatId`로 scope를 재검증하고, 다른 방에는 존재 정보를 노출하지 않는다.
- prompt, OAuth token/device code, CLI raw output, local artifact path, 카카오 원문은 log·metric·상태 응답에 남기지 않는다.
- readiness/doctor는 생성 명령을 실행하지 않는다. 유료 canary는 명시적 비용 승인·상한·운영자 확인을 모두 요구한다.
- `VIDEO_ZDR_UPLOAD_URL_REQUIRED`는 무제한 재시도 대상이 아니다. 동일 idempotency job에는 60초 이상 뒤 **1회만** 제한 재시도하고, 다시 실패하면 circuit-open·사용자 일반 오류로 끝낸다.
- CLI에 검증된 video capability가 없거나 native Kakao video delivery가 불가능하면 우회 경로를 추가하지 않고 계획을 blocked로 기록한다.
