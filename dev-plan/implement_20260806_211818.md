# implement_20260806_211818.md

작성 일시: `2026-08-06 21:18:18 KST`

이 문서는 톡방 수신 영상의 실제 해상도가 너무 낮은 문제를 해결하기 위해 YouTube
다운로드 MP4의 서버 출력 품질을 올리는 범위를 고정한다.

## 개발 목적

현재 5~10분 영상이 서버에서 이미 `426×240 / 180kbps`로 축소돼 Android direct-share 이전부터
품질이 낮다. 카카오톡의 후속 처리로 더 흐려지는 현상을 줄이도록, 처리 시간과 파일 크기를
제한한 고품질 균형 프로필로 바꾼다.

## 개발 범위

- YouTube 다운로드의 기본 출력 profile을 480p/360p/270p 단계로 상향한다.
- 가로·세로 원본 모두에서 긴 변 기준 해상도가 보존되도록 orientation-aware scale filter를 적용한다.
- server hard limit/target을 42MiB/38MiB로 조정하되 Android 50MiB transport guard 안에 둔다.
- H.264 Baseline, yuv420p, AAC, faststart 및 duration/size safety ceiling은 유지한다.
- profile 단위 테스트, proxy-youtube build/test, launchd 재기동 후 read-only health/설정 검증을 수행한다.
- 사용자 도움말과 운영·proxy 문서를 실제 기본 출력으로 갱신한다.

## 제외 범위

- 생성 영상·펜브러쉬 영상의 생성 모델 해상도 변경
- KakaoTalk 내부 재인코딩 규칙 제어 또는 UI 자동화
- 다운로드 명령에 고화질/저화질 옵션을 새로 추가하는 기능
- 사용자 명시 없는 실제 YouTube 다운로드·카카오톡 전송 canary

## 확인·결정 기록

| 항목 | 결과 / 결정 |
| --- | --- |
| 저품질 직접 원인 | 현재 `selectKakaoLiteProfile()`이 5~10분을 426×240·180kbps, 10~15분을 320×180·110kbps로 강제한다. |
| Android 영향 | Android `Replier`는 최종 MP4를 재인코딩하지 않는다. 저해상도는 서버 출력이 주원인이고 Kakao 후속 압축은 악화 요인이다. |
| 세로 영상 결함 | 기존 `width×height` 상한은 세로 소스에서 270×480 이하로 축소될 수 있다. 가로/세로 별 long-edge 상한을 사용한다. |
| 출력 정책 | 3분 이하 854×480/1.1Mbps, 3~5분 854×480/0.88Mbps, 5~10분 640×360/0.40Mbps, 10~15분 480×270/0.26Mbps를 선호값으로 사용한다. 실제 bitrate는 38MiB target VBV ceiling 이하로 조정한다. |
| 전송 지연 | 고품질 파일도 기존 5~20분 DB confirmation 정책으로 처리한다. 느리다는 이유만으로 재전송하지 않는다. |

## 공통 진행 규칙

- 각 Phase는 앞선 Phase의 자체 테스트 완료 뒤에만 진행한다.
- 출력 품질은 해상도만이 아니라 duration·bitrate·최종 byte cap을 함께 검증한다.
- H.264 Baseline/yuv420p/faststart 및 chat-scoped artifact 보안 계약을 약화하지 않는다.
- 신규 호출어를 만들지 않으며, 현재 명령의 기본 결과만 바꾼다.
- Android 실기기는 PD20 `0123456789ABCDEF`만 사용하고 ADB·DB·코드 기반으로 검증한다.
- 실제 카카오톡 전송 canary는 별도 명시 요청 없이는 실행하지 않는다.
