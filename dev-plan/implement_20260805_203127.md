# implement_20260805_203127.md

작성 일시: `2026-08-05 20:31:27 KST`

이 문서는 카카오톡방에서 `헤이봇 유튜브 다운로드 <YouTube 링크>`를 실행하면
허용된 단일 공개 YouTube 영상을 MP4로 가져와 같은 방에 첨부 전송하고, Kakao DB
기록까지 확인하는 기능의 구현 범위를 고정한다.

## 개발 목적

사용자가 YouTube 링크를 다시 내려받거나 별도 앱을 거치지 않아도, 헤이봇이 허용된
방에서 요청을 작업화하고 영상 파일을 카카오톡방으로 전송한다. 생성형 영상 기능과
분리된 다운로드 전용 프록시를 사용하고, 서버의 외부 미디어 취득·Android의 카카오
전송·DB confirmation을 각각 최소 책임으로 분리한다.

완료 기준은 **다운로드 작업 성공이 아니라 카카오 DB에 전송된 영상 첨부 행이 확인된
상태**다.

## 개발 범위

- 정확한 사용자 명령 `헤이봇 유튜브 다운로드 <YouTube 링크>` 및 상태·취소·재전송·삭제 명령
- 중앙 control room 관리자만 변경 가능한 방별 `YOUTUBE_DOWNLOAD` capability
- 단일 `youtube.com`/`youtu.be` 공개 영상 URL 정규화·검증 및 playlist/channel/batch 거부
- `yt-dlp` 고정 버전과 FFmpeg를 사용하는 격리 `proxy-youtube` job service
- 고정된 MP4(H.264 video/AAC audio) 전달 형식, 크기·길이·시간·동시 작업 상한
- Android의 작업 poll·MP4/크기/SHA-256 검증·Kakao direct share·DB confirmation
- 전송 미확인 시 1회 자동 재시도, 이후 `헤이봇 유튜브 재전송`으로 기존 결과만 재전송
- 서버·Android 임시 파일 TTL 삭제, 취소·삭제·재시작 복구, trace·운영 상태·도움말
- Node/Android 단위·통합 회귀와 PD20 `0123456789ABCDEF` 제한 E2E

## 제외 범위

- 재생목록·채널·Shorts 묶음·라이브·비공개·로그인/연령 인증 필요 영상의 다운로드
- 브라우저 cookie, Google 계정, DRM/접근 제한 우회, 사용자가 제공한 임의 `yt-dlp` 옵션
- 다중 플랫폼 downloader, 음원만 추출, 자막/전사/음성 요약, 파일 편집·재인코딩 UI
- YouTube 원본과 Kakao 업로드 완료본의 영구 저장, 일반 공개 다운로드 링크 제공
- 생성형 `proxy-video`, Grok 비디오, 기존 MP3/M4A/WAV 음성 요약의 동작 변경

  요청하도록 안내하되, 복잡한 OAuth 권리 검증은 별도 범위로 둔다.

- `proxy-youtube`는 생성형 `proxy-video`와 job store·endpoint·권한을 섞지 않는다. 공통화는

- cookie·secret·서명 URL·원본 영상 바이트·상세 extractor stderr을 Git, trace, 사용자 메시지에 남기지 않는다.
- yt-dlp/FFmpeg의 정확한 배포물 버전·SHA-256·라이선스/제3자 고지 파일을 pin하고, 검증 전 자동 업데이트하지 않는다.
- Android 실기기 검증은 PD20 `0123456789ABCDEF`와 ADB·DB·코드만 사용한다.
- 신규 호출어는 parser/router, `HeybotSkillCatalog`, 운영 문서, 테스트를 같은 변경에서 갱신한다.

## Phase 3. Kakao DB confirmation·재전송·정리

### 목표

카카오 direct-share dispatch와 실제 Kakao DB attachment 확인을 분리해, 미확인 영상을 안전하게
보류·재전송하고 원본을 정리한다.

### 구현 태스크

- [ ] bot-authored video attachment를 job/attempt와 상관시킬 수 있는 `VideoDeliveryTracker` 또는 검증된 공통 delivery contract를 구현한다. 텍스트 digest tracker를 영상에 재사용하지 않는다.
- [ ] `delivery_pending → delivered` 전이를 Kakao DB attachment confirmation 후에만 수행하고 실제 result log ID·attempt count만 bounded state에 저장한다.
- [ ] timeout에는 같은 검증 파일의 1회 자동 direct-share 재시도를 수행한다. 두 번째 미확인만 `awaiting_resend`으로 전이한다.
- [ ] `헤이봇 유튜브 재전송`은 요청자·같은 방·미확인 job만 대상으로 하며, remote downloader를 재실행하지 않는다.
- [ ] 취소/삭제/capability revoke/restart 시 pending waiter·Android temp file·server TTL purge가 경합하지 않게 한다.
- [ ] status/실패 안내에는 `다운로드 실패`, `파일 검증 실패`, `카카오 전송 확인 대기`를 구분하고 정상 확인 뒤 재전송 안내를 보내지 않는다.
