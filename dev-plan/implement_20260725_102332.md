이 문서는 PD20 Iris의 호출어 기반 GLM과 전역 일반대화에 대해 응답 안전성, 운영 이상 자동 정지, 방·사용자별 정책 경계를 추가하기 위한 작업 문서다. 기존 직접 Z.AI GLM 구조와 코어라인 AI 연구소 단일 관리자 control room 정책을 유지한다.

## 개발 목적

전역 일반대화가 활성화된 경우에도 허용한 방·사용자만 GLM arbitration 후보가 되게 하고, 모델 답변이 토큰·운영 비밀·개인정보 형식을 노출하지 않도록 전송 직전에 검사한다.

일반대화에서 GLM timeout·429·네트워크/서버 오류가 짧은 시간에 누적되면 **일반대화만** 자동 OFF한다. 호출어 기반 GLM 질문, 이미지 작업, Iris 수동 `/reply`는 계속 동작해야 한다.

## 개발 범위

- 모든 텍스트 GLM 답변의 전송 직전 deterministic reply safety policy
- secret-like 값 차단, 개인정보 패턴 redaction, 정책 차단 사유의 원문 없는 metric
- `IRIS_GENERAL_CONVERSATION_ALLOWED_CHAT_IDS`의 explicit 일반대화 방 allowlist
- root 전용 user block 정책 파일: 전역 `userId` 및 `(chatId,userId)` exact block
- 일반대화 request만 관측하는 rolling-window circuit breaker
- timeout·429·network·server 실패 누적 시 mode epoch 무효화와 자동 OFF
- 코어라인 AI 연구소 관리자 `대화 상태`·`설정 보기`에 정책/자동 정지의 비밀 없는 상태 표시
- JVM 단위·회귀 테스트, release APK build, PD20 제한 E2E, 일반대화 단독 롤백 문서

## 현재 기준 상태

- 일반대화 mode는 코어라인 AI 연구소 control room의 exact 관리자만 start/status/stop 할 수 있다.
- mode ON이면 현재는 `IRIS_GLM_ALLOWED_CHAT_IDS` 전체의 비호출어 텍스트가 arbitration 후보가 된다.
- `GeneralConversationArbiter`는 strict `REPLY/WAIT/IGNORE` JSON을 검증하지만, REPLY 본문의 token·개인정보 형식은 별도 정책 검사 없이 전송한다.
- `BotMetrics`는 누적 성공/실패·429·timeout을 보유하지만, 일반대화만의 최근 오류율·자동 OFF 상태는 없다.
- room/user rate limit과 duplicate drop은 존재하지만, 일반대화 전용 방 allowlist와 user block 정책은 없다.

## Phase 3. 일반대화 circuit breaker와 관리자 관측

### 목표

### 구현 태스크

- [x] `GeneralConversationCircuitBreaker`에 5분 rolling window·3회 external failure threshold를 구현한다.
- [x] timeout·429·network·server failure만 circuit signal로 넣고, duplicate·user rate limit·queue full·invalid JSON은 signal에서 제외한다.
- [x] threshold trip 시 mode stop과 epoch 증가를 원자적으로 수행해 기존 queued/in-flight REPLY를 보내지 못하게 한다.
- [x] `헤이봇 대화 시작`은 circuit 상태·failure window를 reset한 뒤 mode를 켠다.
- [x] `헤이봇 대화 상태`와 설정 보기에는 mode 상태, allowlisted 방 수, circuit 상태, 마지막 generic category만 표시한다.
- [x] circuit trip은 일반대화의 사용자 오류 메시지 대신 관리자 status에서만 확인 가능하게 한다.

## 잔여 리스크 / 후속 과제

- 정규식 기반 PII/secret 검사는 완전한 콘텐츠 안전 시스템이 아니며, false positive/negative를 generic counter만으로 관찰해야 한다.
- circuit threshold는 초기 보수값이다. 실제 방별 traffic과 Z.AI 품질을 관찰한 뒤 별도 계획에서만 조정한다.
- user block 정책의 변경은 root 파일 교체·Iris 재기동이 필요하다. 카카오 명령 기반 정책 변경은 별도 권한 감사 설계 없이는 추가하지 않는다.
