# implement_20260805_192026.md

작성 일시: `2026-08-05 19:20:26 KST`

이 문서는 R01 음성 STT·요약의 후속 신뢰성 범위인 엄격한 증거 JSON, 카카오 multipart
각 part 확인·재전송, 안전한 음성 결과 후속 대화 문맥을 구현하기 위한 작업 문서다.

## 개발 목적

LLM이 만든 음성 요약을 자유 텍스트로 신뢰하지 않고 전사 segment에 연결된 제한 JSON으로
검증한다. 카카오톡 결과가 여러 part일 때는 각 part의 DB 행 확인을 마친 뒤에만 완료 처리하며,
확인되지 않은 part는 1회 자동 재전송한 뒤에도 확인되지 않을 때만 명시적으로 재전송한다. 모든 part가 확인된 안전 요약은 같은 방의 대화
문맥으로 제한 저장해, 사용자가 결과에 대해 자연스럽게 이어서 질문할 수 있게 한다.

## 개발 범위

- `AudioSummaryGenerator`의 map/reduce 출력을 strict JSON schema로 전환하고 한 번만 repair
- claim·결정·액션의 evidence segment ID 존재, enum·key·문자 수·배열 수·날짜/담당자 규칙 검증
- schema 실패는 `SUMMARY_OUTPUT_INVALID`로 fail-closed하고 raw LLM 출력은 저장·전송하지 않음
- `[n/N]` multipart를 순서대로 보내고 각 part를 `TextDeliveryTracker`의 Kakao DB confirmation으로 확인
- 확인되지 않은 part는 `헤이봇 음성 재전송`으로만 재시도하고 재전송 표기를 달아 digest 혼동을 방지
- 최종 모든 part DB 확인 후에만 root-only atomic store에 safe summary·결과 log ID만 저장
- owner는 30분 내 후속 대화, 다른 참여자는 결과 exact reply 또는 짧은 명시 참조만 허용
- 삭제·내 기억 초기화·전체/사용자 기억 초기화에서 audio context도 함께 제거

## 제외 범위

- STT 재실행, 화자 식별, transcript 장기 보관/RAG, 새 room capability
- 카카오 전송의 exactly-once 보장 또는 서버 측 카카오 API 전환
- LLM이 evidence의 사실성을 의미적으로 판정하는 작업
- 기존 Vision context의 동작·TTL·저장 형식 변경
- 새 외부 라이브러리·서버 endpoint·DB schema 도입
