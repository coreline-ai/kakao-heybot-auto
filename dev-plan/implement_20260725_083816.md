이 문서는 Android PD20에서 실행되는 Iris GLM 자동응답의 P1 운영 안정성 개발 범위를 고정하고, 구현이 Mac 프록시나 다른 기능으로 확장되지 않도록 하기 위한 작업 문서다.

## 개발 목적

현재 허용된 3개 오픈방이 공유하는 단일 GLM actor를 방별 FIFO 처리 구조로 변경하고, 전체 동시성 제한·호출 제한·관리자 권한·사용자별 대화 기억 영속화·도움말과 상태 모니터링을 추가한다.

한 방의 GLM 요청이 최대 120초 지연돼도 다른 방의 대화와 로컬 명령이 처리되어야 하며, Iris 재시작 후에도 사용자별 대화 기억과 필요한 운영 상태를 안전하게 복구할 수 있어야 한다.

## 현재 기준 상태

- `GlmAutoReplyHandler` 인스턴스 하나가 모든 허용 방을 처리한다.
- 단일 `Channel` 용량은 16이고 GLM 처리 동시성은 1이다.
- 한 요청이 API·retry·fallback을 수행하는 동안 다음 방 요청도 대기한다.
- 현재 대화 기억 키는 `chatId`이고 최근 4턴·30분만 메모리에 유지한다.
- Iris 재시작 시 대화 기억이 모두 사라진다.
- 동일 `logId` 재처리는 막지만 같은 내용의 새 메시지는 막지 않는다.
- 방·사용자 호출량 제한과 관리자 권한이 없다.

## 잔여 리스크 / 후속 과제

- 전체 GLM 동시성 2가 Z.AI 계정 제한에 맞는지 PD20 실측 후 조정해야 한다.
- 사용자별 분당 5회 기본값은 실제 사용 패턴에 따라 조정할 수 있다.
- root 전용 JSON이라도 대화 원문이 저장되므로 TTL·권한·백업 범위를 운영 정책으로 관리해야 한다.
- 프로세스 강제 종료 시 running GLM 요청은 복구할 수 없으며 queued request 복구 여부를 별도 정책으로 확정해야 한다.
- Android 로컬 상태 화면이나 외부 모니터링은 P1 이후 별도 계획으로 분리한다.
