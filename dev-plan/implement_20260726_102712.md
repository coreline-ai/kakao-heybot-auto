# implement_20260726_102712.md

작성 일시: `2026-07-26 10:27:12 KST`

이 문서는 헤이봇의 호출어 대화와 일반대화에 대해 **동일한 대화 프롬프트·문맥·안전정책을 유지한 채**, 응답 엔진만 Android 내장 GLM, Codex 프록시, Grok 프록시 중 하나로 전환하는 개발 범위를 고정한다.

## 개발 목적

현재 헤이봇은 Android의 GLM만으로 호출어 대화와 일반대화를 생성한다. 이를 다음과 같이 확장한다.

```text
기본: GLM (Android 내부)
선택: Codex (proxy-manager → conversation → proxy-codex)
선택: Grok  (proxy-manager → conversation → proxy-grok)
```

코어라인 AI 연구소의 지정 관리자만 아래 명령으로 **모든 텍스트 허용방의 대화 엔진**을 전역 변경할 수 있어야 한다.

```text
헤이봇 대화 기본      # GLM
헤이봇 대화 코덱스    # Codex
헤이봇 대화 그록      # Grok
헤이봇 대화 상태      # 일반대화 상태와 현재 엔진을 함께 표시
```

호출어 대화와 호출어 없는 일반대화는 모두 같은 엔진 선택을 사용한다. 다만 호출어 대화용 기본 프롬프트와 일반대화의 `REPLY/WAIT/IGNORE` 판단 프롬프트라는 **현재 두 종류의 목적별 프롬프트**는 유지하며, 엔진별로 문구·성격을 다르게 만들지 않는다.

## 개발 범위

- `GLM`, `CODEX`, `GROK` 전역 대화 엔진 모드와 root 전용 영속 저장소 추가
- 코어라인 AI 연구소의 exact 관리자만 실행할 수 있는 엔진 전환·상태 명령 추가
- 기존 GLM 호출부를 provider-neutral `ConversationGateway` 계약으로 분리
- Android에 GLM adapter와 manager 경유 Codex/Grok adapter를 추가
- 신규 gateway domain `proxy-conversation`을 만들고 manager의 `/v1/conversation` route로 노출
- `proxy-codex`, `proxy-grok`에 기존 이미지·영상 contract와 독립적인 `conversation.respond.v1` internal capability 추가
- Codex 이미지 작업과 Grok 영상 작업이 텍스트 대화를 막지 않도록 capability별 bounded queue 분리
- 기존 `(chatId, userId)` 문맥, room capability, 일반대화 arbitration, safety sanitizer, circuit breaker, Kakao 전송 성공 뒤 memory commit을 엔진 공통으로 유지
- launchd/watchdog, ADB reverse 단일 manager ingress, readiness, 운영 문서, 자동 테스트 및 제한 E2E 추가

## 제외 범위

- GLM을 Mac 서버로 이전하거나 Android GLM 기본 경로를 제거하는 작업
- Codex/Grok가 현재 수행하는 이미지·영상 생성 API의 요청/응답 contract 변경
- Codex/Grok CLI의 임의 shell 명령, 파일 작업, 브라우저/도구 사용을 채팅에서 노출하는 기능
- 엔진별 별도 페르소나 프롬프트, RAG, 웹 검색, 방 전체 공유 문맥, 장기 대화 아카이브
- 방마다 다른 엔진을 고르는 UI 또는 일반 사용자의 엔진 전환 권한
- 외부 공개 URL, 텍스트 원문·프롬프트·CLI 원문 출력·secret의 상태 응답 또는 로그 기록
- 영상/펜브러쉬/image capability 정책의 의미 변경

## 결정 기록

| 항목 | 결정 |
|---|---|
| 제품명·명령어 | 오타인 `코비서`를 사용하지 않는다. 관리자 명령은 `헤이봇 대화 기본/코덱스/그록/상태`로 고정한다. 기존 `헤이봇 대화 시작/종료`와 충돌하지 않는다. |
| 모드 적용 범위 | 하나의 전역 모드가 모든 `TEXT` 허용방의 호출어 대화와 `GENERAL_CONVERSATION` 허용방의 일반대화에 적용된다. |
| 모드 권한 | 코어라인 AI 연구소의 exact admin `userId`만 변경·상태 확인할 수 있다. 다른 방과 일반 사용자는 거부한다. |
| 기본값·복구 | 모드 파일이 없거나 손상되거나 proxy 설정이 준비되지 않으면 GLM으로 fail-closed 복구한다. Codex/Grok 모드는 명시 변경 전에는 켜지지 않는다. |
| 설정 저장 | Android root 전용 원자 파일에 `schemaVersion`, `engine`, `updatedAt`만 보관한다. 대화 원문·관리자 ID·secret은 저장하지 않는다. |
| 프롬프트 | 호출어용 `SYSTEM_PROMPT`와 일반대화용 strict arbitration prompt는 현재 문구·상한을 유지하고, 세 엔진에 동일한 role/message 순서로 전달한다. transport/output 제약만 provider adapter에 둔다. |
| 문맥 소유자 | Android의 기존 `ConversationMemoryStore`가 유일한 문맥 정본이다. proxy는 요청 처리 중에만 문맥을 사용하고 저장하지 않는다. |
| 외부 경로 | PD20은 manager `POST /v1/conversation/respond`만 호출한다. Android가 Codex/Grok 포트나 CLI에 직접 접속하지 않는다. GLM은 Android 내부에서만 호출한다. |
| proxy 경계 | 새 `proxy-conversation`은 domain gateway다. `proxy-codex`/`proxy-grok`은 각 CLI·capability·workspace·queue만 책임지고 Kakao/방 정책을 모른다. |
| 텍스트 contract | `conversation.respond.v1`은 bounded text만 반환한다. artifact, tool 실행 결과, shell argv, path, child output은 반환하지 않는다. |
| queue | Codex image와 Grok video의 느린 job이 텍스트 대화를 점유하지 않도록 provider별 text queue를 media queue와 분리한다. text queue에도 전역 동시성·pending 상한·timeout을 둔다. |
| 오류 처리 | Codex/Grok timeout, 429, auth, queue-full, malformed output은 실패로 처리한다. 사용자가 알지 못하게 GLM으로 자동 전환하지 않는다. 호출어 대화는 짧은 안내를 보낼 수 있고, 일반대화는 기존 fail-silent/circuit 정책을 유지한다. |
| 안전 처리 | Android의 room capability, admission/rate limit, sanitizer, delivery 직전 revision 재확인, Kakao 전송 성공 후 memory commit을 공통 경계로 유지한다. |

## 공통 진행 규칙

- 각 Phase는 앞선 Phase의 자체 테스트와 완료 조건을 통과한 뒤에만 시작한다.
- 구현 중 발견한 이슈는 해당 Phase에서 수정·기록하며, 체크박스는 실제 상태와 일치시킨다.
- 모든 listener는 `127.0.0.1`에만 bind한다. PD20은 기존 ADB reverse/LAN 연결의 manager `4340`만 사용한다.
- 대화 payload는 TLS가 아닌 loopback/ADB-reverse 구간이더라도 no-store 처리하고, access log·SQLite·crash report에 원문을 남기지 않는다.
- `chatId`, `userId`, `logId`는 HTTP 경계에서 decimal string으로 전달하고, 수신 측에서 양의 정수/길이/상한을 검증한다.
- Android의 `TEXT`, `GENERAL_CONVERSATION` capability와 general mode, block policy, circuit breaker가 provider 전환으로 약화되지 않아야 한다.
- 기존 Codex image와 Grok video route/capability/canary는 text 기능과 독립적으로 계속 동작해야 한다.
- 새 의존성은 현재 Node/Kotlin 표준 기능으로 해결할 수 없을 때만 추가한다. CLI 실행은 allowlist capability와 고정 runner로만 수행한다.
- CLI의 실제 모델·옵션·텍스트 출력 형식은 Phase 0 smoke에서 확인 후 config로 고정한다. 사용자 입력이 이를 변경할 수 없다.
- APK 배포, launchd 활성화, 실제 Codex/Grok 호출, 카카오 E2E는 각 단계의 명시적 확인 범위에서만 실행한다.

## Phase 0. 명령·공통 contract·CLI text 가능성 확정

### 목표

구현 전 사용자 명령, provider-neutral 대화 요청/응답, 현재 CLI의 안전한 text-only 실행 방식을 고정한다. 이 단계에서는 Android 동작과 운영 registry를 변경하지 않는다.

### 구현 태스크

- [x] `ConversationEngine = GLM | CODEX | GROK`와 `ConversationKind = WAKE_WORD | GENERAL_CONVERSATION`의 Android/domain 공통 enum·wire value를 확정한다.
- [x] `헤이봇 대화 기본`, `헤이봇 대화 코덱스`, `헤이봇 대화 그록`, `헤이봇 대화 상태`의 exact-prefix parser와 기존 start/status/stop의 출력 병합 규칙을 확정한다.
- [x] request v1을 `requestId`, `engine`, `kind`, bounded `messages`, fixed `promptVersion`으로, response v1을 `requestId`, `engine`, bounded `text`, `latencyMillis`로 구현했다.
- [x] `GLM` 요청은 manager에 보내지 않고 Android `GlmClient` adapter를 사용하며, `CODEX`/`GROK`만 `/v1/conversation/respond`로 보내도록 분기했다.
- [x] Codex CLI와 Grok CLI에서 무해한 Korean text fixture로 text-only 실제 응답을 확인했다.
- [x] provider별 결과에서 최종 assistant text만 추출하고 artifact/tool 결과는 실패 처리하는 contract를 구현했다.
- [x] 현재 호출어 prompt와 일반대화 strict JSON prompt를 provider-neutral message envelope로 유지했다.

### 자체 테스트

## 잔여 리스크 / 후속 과제

- Codex/Grok CLI의 text-only machine-readable output 또는 account policy가 Phase 0에서 충분히 안정적이지 않으면 해당 provider를 준비되지 않음으로 유지하고 GLM/Codex 또는 GLM/Grok 조합만 먼저 활성화한다.
- 외부 provider의 지연·429·사용량은 GLM보다 변동이 크므로, 사용량 제한·provider별 circuit threshold 조정은 제한 E2E 측정값을 근거로 별도 계획에서 결정한다.
- room별 engine 선택, 방 전체 공유 문맥, provider별 프롬프트 튜닝은 이번 전역 엔진 선택이 안정화된 뒤 별도 요구사항으로 분리한다.
