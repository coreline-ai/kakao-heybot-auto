이 문서는 코어라인 AI 연구소의 정확한 관리자만 각 오픈방의 텍스트·일반대화·이미지
권한을 즉시 변경할 수 있게 하는 개발 범위를 고정한다. 현재처럼 시작 스크립트의
allowlist를 수정하고 Iris를 재기동하는 운영 절차를 중앙 관리자 명령으로 대체한다.

## 개발 목적

코어라인 AI 연구소에서 `헤이봇 방 목록`과 방별 권한 변경 명령을 실행하면, 대상 방의
헤이봇 기능을 재기동 없이 즉시 허용·불허용한다. 권한의 실제 식별자는 변경되지 않는
`chatId`이며, 방 이름은 목록 표시에만 사용한다.

## 개발 범위

- 코어라인 AI 연구소의 exact 관리자 전용 방 권한 명령과 확인/취소 흐름
- 관리 가능한 방의 정적 상한(catalog)과 동적 capability policy의 분리
- 방별 `text`, `generalConversation`, `image` capability의 저장·원자적 갱신·즉시 반영

## 명령 계약

```text
헤이봇 방 목록
헤이봇 방 상태 R02

헤이봇 방 텍스트 허용 R02
헤이봇 방 일반대화 불허용 R02
헤이봇 방 이미지 허용 R02

헤이봇 방 적용 <nonce>
헤이봇 방 취소
```

- `방 목록`은 `R01` 같은 참조값, 표시 이름, 세 capability의 허용 상태만 보여준다.
- 변경 명령은 대상·이전값·예정값·짧은 nonce만 보여주며 아직 저장하지 않는다.
- `적용`은 같은 관리자·같은 control room·미만료 nonce와 정확히 일치할 때만 수행한다.
- unknown 참조값, 잘못된 capability/action, 다른 관리자의 nonce, 만료 nonce는 모두 변경 없이 거부한다.

## 공통 진행 규칙

- 각 Phase는 앞선 Phase의 자체 테스트 완료 후에만 시작한다.
- `chatId`·`userId`는 decimal positive `Long` exact match만 허용한다. 방 이름·닉네임·메시지 원문으로 권한을 판단하지 않는다.
- 모든 policy read/write는 원자성, `600 root:root`, schema version, 최대 크기 제한을 검증한다.
- control room 이외에서는 방 제어 명령을 실행하지 않는다. 비관리자·다른 방·잘못된 nonce는 정책 파일을 절대 변경하지 않는다.
- capability가 불허용으로 바뀐 뒤 queue/in-flight 작업이 늦게 답장하지 않도록 send 직전에 현재 snapshot을 다시 검증한다.
- 정책 상태·감사 로그에는 방 이름 별칭과 generic 결과만 남기며, 사용자 ID·대화 원문·secret·정책 파일 원문은 남기지 않는다.
- APK 배포, PD20 재기동, root 정책 파일 변경, 실제 카카오 E2E는 사용자 요청 범위 안에서만 실행한다.
