이 문서는 PD20 Iris HTTP 관리 API의 무인증 노출을 차단하는 P0 보안 개발 범위를
고정한다. 카카오 메시지 수신·GLM 자동응답·이미지 생성의 운영 흐름은 유지하되,
Mac의 상시 ADB forward와 인증 없는 관리 API를 제거한다.

## 개발 목적

- 실행 중인 Iris HTTP API의 인증 없는 대화·AOT·발신·복호화·설정 변경 경로를 차단한다.
- `adb forward tcp:3000 tcp:3000`의 시작/감시 자동 복원을 없애 Mac localhost의 상시 관리 포트를 제거한다.
- Iris HTTP 관리 기능이 필요할 때만 root 전용 비밀로 인증된 loopback API를 명시적으로 활성화한다.
- root Iris 설정과 로그를 `/data/local/private`로 옮기고 대화 원문·설정 전문을 로그에 남기지 않는다.

## 개발 범위

- Iris HTTP API의 **기본 비활성화(fail-closed)** 및 명시적 활성화 설정
- HTTP server의 `127.0.0.1` 명시 bind, admin bearer 인증, generic error 응답
- `/health` 최소 익명 endpoint 분리 및 기존 `/config` health check 제거
- 운영 API에서 `/aot`, `/query`, `/decrypt` 제거
- `/reply`, `/dashboard`, `/config`, `/ws`의 admin 인증 강제 및 위험한 `config/endpoint` 변경 비활성화
- `/data/local/private/iris-config.json`, Iris 로그, HTTP admin secret의 `root:root`·`600` 운영 계약
- PD20 시작 스크립트와 watchdog에서 영구 `tcp:3000` forward 제거
- JVM/스크립트 회귀 테스트, 제한된 PD20 검증·롤백 문서

## 문서 기반 제약 사항

- `tcp:4340`의 `adb reverse`는 PD20 → Mac image proxy 경로이므로 유지한다.
- `tcp:3000`의 `adb forward`만 제거 대상이다. 이를 제거해도 GLM 자동응답과 이미지 proxy 호출은 계속 가능해야 한다.
- secret은 기존 GLM key, proxy route secret과 공유하지 않는다. HTTP admin 전용 secret을 별도 파일로 둔다.
- HTTP secret 누락·파일 권한 오류·설정 parse 오류에서는 **Iris 봇 전체가 아니라 HTTP 관리 API만 비활성화**한다. GLM/이미지 봇 처리는 계속한다.
- `/health`는 인증 없이 허용하되 서비스명·ready boolean 외 대화/설정/버전/경로/queue 정보를 반환하지 않는다.
- 배포·ADB forward 제거·PD20 재기동·AOT 재인증은 실제 운영 변경이므로 구현 및 자동 테스트 완료 후 사용자 승인으로만 실행한다.

## 잔여 리스크 / 후속 과제

- Mac 또는 rooted PD20의 root 권한 탈취 자체는 secret file mode만으로 방어할 수 없다. 운영 계정·ADB 승인·물리 접근 통제는 계속 필요하다.
- SEC-004 호출어 privacy 정책, SEC-005 manager reserved header, SEC-006 Node timeout은 이 계획 완료 후 별도 보안 hardening 계획으로 처리한다.
- Kakao AOT가 과거 무인증 endpoint에 노출됐을 가능성은 코드 수정만으로 소급 해소되지 않는다. 세션 재인증 필요성은 운영자가 Kakao 계정 상태를 보고 결정한다.
