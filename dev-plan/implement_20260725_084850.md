이 문서는 PD20 Iris와 Mac 프록시 플랫폼 사이의 인증·방 범위·상시 운영·전송 경계를 구현하기 위한 작업 범위를 고정한다. 이미지·Codex 기능 자체보다 먼저, 안전한 연결과 복구 가능한 운영 기반을 만든다.

## 개발 목적

PD20 Iris가 Mac의 `proxy-manager`만 제한적으로 호출하게 하고, 각 요청이 허용된 카카오 `chatId` 범위를 벗어나거나 내부 프록시·관리 수명주기 권한으로 확대되지 않게 한다. Mac 재시작, proxy crash, USB/ADB 단절 뒤에도 자동으로 health를 판단하고 ADB reverse를 복구한다.

초기 운영 경로는 **USB ADB reverse + Mac loopback**만 허용한다. LAN 직접 연결은 USB 경로의 장시간 검증이 끝난 뒤에만 별도 활성화한다.

## 현재 기준 상태

- `proxy-manager`, `proxy-image`, `proxy-codex`는 문서·예시 설정만 있고 런타임 소스가 없다.
- 계획된 manager port는 `4340`, 모든 proxy target은 `127.0.0.1` loopback이다.
- PD20 Iris GLM은 독립적으로 동작하며 proxy-manager 연결은 아직 없다.
- PD20 재연결 시 ADB mapping이 사라질 수 있고, 현재 이를 복구하는 watchdog은 없다.
- 현재 Iris manual control API는 별도 방어 경계이므로 이 계획의 proxy route credential과 혼동하지 않는다.

## 인증·권한 경계

```text
PD20 Iris
  route.secret
    -> proxy-manager :4340
       (route secret 검증 후 inbound Authorization 제거)
       -> proxy-image :4347
          manager-image.secret
          -> proxy-codex :4348
             image-codex.secret + serviceId=image + capability=image.generate

Mac operator
  admin.secret
    -> proxy-manager lifecycle API (기본 OFF)
```

| Secret | 보유 주체 | 금지 대상 | 용도 |
|---|---|---|---|
| `route.secret` | PD20 Iris, proxy-manager | domain/engine proxy, CLI child | PD20 → manager gateway |
| `manager-image.secret` | proxy-manager, proxy-image | PD20, proxy-codex, CLI child | manager → image |
| `image-codex.secret` | proxy-image, proxy-codex | PD20, manager route, CLI child | image → codex capability |
| `admin.secret` | Mac operator, proxy-manager | PD20, 모든 domain/engine proxy | lifecycle/test 관리 |

- secret 값은 `.env`, registry JSON, APK, source, request/response, metric, log에 기록하지 않는다.
- 각 process는 필요한 secret **파일 경로**만 설정으로 받는다. 다른 package의 runtime directory를 읽지 않는다.
- Codex child 환경에는 `PATH`, `HOME`, `CODEX_HOME`, `TMPDIR`, locale처럼 필요한 값만 allowlist하고 모든 service secret을 제외한다.
- missing/invalid secret은 `401`, 유효한 route credential이지만 room scope를 벗어나면 `403` 또는 resource enumeration을 막는 generic `404`로 처리한다.

## Room scope 계약

1. Iris가 명령을 해석할 때 허용 `chatId`와 requester 정책을 먼저 검사한다.
2. manager는 `chatId`, `logId`, `requesterId`를 JavaScript number가 아닌 decimal string schema로 검증한다.
3. manager와 domain proxy는 독립적으로 `allowedChatIds` 정책을 검사한다.
4. `jobId`만으로 status/file/cancel에 접근할 수 없다. 모든 요청은 `chatId`를 함께 보내고 storage query도 `WHERE job_id = ? AND chat_id = ?`로 제한한다.
5. domain job은 접수 당시의 불변 `chatId`만 저장·전달한다. 마지막 수신 방이나 전역 current room을 사용하지 않는다.
6. 관리자 명령은 route secret과 별개로 Iris가 Kakao DB의 exact `userId`를 검사한다. manager admin secret을 카카오 채팅에 전달하거나 관리자 ID로 대체하지 않는다.

권장 request 예시:

```http
POST /v1/image/jobs
Authorization: Bearer <route secret>
Content-Type: application/json

{
  "requestId": "iris-1703",
  "chatId": "18480337854645134",
  "requesterId": "444000000",
  "logId": "1703",
  "prompt": "..."
}
```

## ADB reverse와 LAN 정책

### USB 기본 경로

```text
PD20 Iris -> http://127.0.0.1:4340
                 ADB reverse
Mac proxy-manager -> 127.0.0.1:4340
```

```bash
adb -s 0123456789ABCDEF reverse tcp:4340 tcp:4340
```

- `adb reverse`는 PD20 loopback과 Mac loopback을 ADB transport로 연결하는 것이며 LAN 공개가 아니다.
- manager는 `127.0.0.1`만 bind한다. `0.0.0.0`으로 바꾸지 않는다.
- PD20 disconnect/reboot, ADB server restart 뒤 reverse mapping은 사라질 수 있으므로 watchdog이 재설정한다.
- proxy 장애나 reverse 단절은 image 기능만 degraded로 표시하며 PD20의 GLM 텍스트 자동응답을 중단시키면 안 된다.

### 무선 ADB reverse failover

PD20은 Android 12(API 31)이므로 Android 11 이상 Wireless debugging의 pairing 방식을 사용할 수 있다. USB는 최초 pairing 또는 비상 복구용으로 남기되, USB가 빠졌을 때 Mac과 PD20이 같은 신뢰 Wi-Fi에 있으면 ADB control connection을 복구하고 동일한 reverse mapping을 다시 적용한다.

```text
Mac adb --Wi-Fi--> PD20 wireless debugging
                  -> adb reverse tcp:4340 tcp:4340
PD20 Iris       -> http://127.0.0.1:4340
```

- pairing은 PD20의 Developer options에서 사용자가 수동 승인한다. pairing port와 실제 connect port는 서로 다를 수 있다.
- Android 12에서는 Wi-Fi 재접속 뒤 connect endpoint/port가 바뀔 수 있으므로 watchdog은 고정된 `:5555`를 가정하지 않는다.
- endpoint는 trusted Wi-Fi의 mDNS discovery 또는 운영자가 보관한 현재 connect endpoint로 찾는다. discovery 실패 시 proxy 기능만 degraded로 두고 GLM을 재기동하지 않는다.
- `adb tcpip 5555` legacy mode는 root Android의 넓은 LAN 디버그 포트를 만들 수 있으므로 기본 금지한다. 꼭 필요하면 전용 VLAN·방화벽·명시적 운영 승인을 별도 요구한다.
- Wi-Fi ADB가 연결되면 watchdog은 `adb reverse`를 idempotent하게 재적용하고 PD20 loopback health check로 확인한다.

### LAN 직접 연결 (후속, 기본 OFF)

LAN을 정말 사용해야 할 때만 다음을 모두 충족한다.

- manager가 특정 LAN interface/IP에만 bind하고, macOS 방화벽에서 PD20 고정 IP만 허용한다.
- HTTPS와 PD20 certificate pinning을 사용한다. route bearer secret은 TLS를 대체하지 않는다.
- 가능하면 PD20 client certificate를 추가한 mTLS로 manager ingress를 제한한다.
- USB와 LAN을 자동 전환하지 않는다. `IRIS_PROXY_TRANSPORT=usb_reverse|lan_tls`처럼 명시적 설정만 허용한다.
- direct LAN readiness/canary와 USB rollback 절차를 별도 승인한다.

## launchd·watchdog 구조

```text
launchd
  ai.coreline.heybot.proxy-manager
  ai.coreline.heybot.proxy-image
  ai.coreline.heybot.proxy-codex
  ai.coreline.heybot.transport-watchdog
```

- 각 proxy는 별도 LaunchAgent/process로 실행한다. launchd `KeepAlive`는 process crash만 복구한다.
- `transport-watchdog`은 별도 60초 주기의 짧은 process로, USB device state·trusted Wi-Fi ADB state·manager ready·reverse mapping을 순서대로 검사한다.
- watchdog은 label allowlist만 `launchctl kickstart -k` 할 수 있다. API·환경변수로 임의 label, shell, argv를 받지 않는다.
- startup grace 120초 안의 transient failure는 restart count에 넣지 않는다. grace 뒤 3회 연속 failure면 restart, 10분 cooldown 동안 반복 restart를 막는다.
- `health`는 process 생존, `ready`는 dependency·secret file metadata·queue/storage/CLI readiness를 의미한다. ready 실패가 항상 process restart 사유는 아니며 failure class별 정책을 둔다.
- stdout/stderr은 package별 runtime log로 rotate하고 Authorization, prompt, response body, secret path를 redaction한다.
- manager lifecycle HTTP API는 default `MANAGER_LIFECYCLE_ENABLED=false`를 유지한다. foreground·launchd dry-run·label 검증이 끝난 뒤에만 Mac local admin secret과 함께 활성화한다.
