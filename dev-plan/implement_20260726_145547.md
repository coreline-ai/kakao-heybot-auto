# implement_20260726_145547.md

작성 일시: `2026-07-26 14:55:47 KST`

이 문서는 Android 헤이봇이 자체적으로 기능 상태를 점검하고, 실제 외부 호출·카카오톡 전송은 명시적으로 승인된 단계에서만 수행하도록 통합 self-test 기능을 추가하는 개발 범위를 고정한다.

## 개발 목적

현재 Android Iris에는 135개 JVM 단위 테스트와 startup/readiness 로그가 있지만, 운영 중인 `ai.coreline.heybot.Main`에서 parser·정책·대화 엔진·프록시·DB observer·카카오톡 전송 경로를 한 번에 진단하는 자체 점검 기능은 없다.

관리자 전용 `헤이봇 자체진단`을 추가해 다음을 분리 검증한다.

1. 외부 네트워크·카카오톡 쓰기 없이 실행하는 오프라인 QUICK 진단
2. 비용 없는 proxy/manager/ADB reverse INTEGRATION 진단
3. 기기 내부 DB·NotificationPoller·process 상태를 읽기 전용으로 점검하는 DEVICE 진단
4. 별도 확인이 있을 때만 실제 GLM/Codex/Grok·이미지·영상·펜브러쉬 생성과 시험방 전송을 수행하는 CANARY 진단

## 개발 범위

- `SelfTestMode`, `SelfTestCase`, `SelfTestResult`, `SelfTestReport` 공통 모델 추가
- fake gateway·fake sender·in-memory backend를 활용한 Android 내부 QUICK runner 구현
- parser, room capability, admin authorization, general mode/circuit, memory, queue/admission, sanitizer, engine mode, media command 경계 테스트 연결
- manager/proxy `/ready`와 conversation/image/video/draw/brush readiness를 비용 없이 확인하는 INTEGRATION adapter 구현
- DBObserver·NotificationPoller·Iris process·`/data/local/private` metadata를 읽기 전용으로 확인하는 DEVICE adapter 구현
- 관리자 exact `userId`와 중앙 control room에만 `헤이봇 자체진단 [빠른|통합|기기|카나리]` 명령 허용
- 기존 `헤이봇 상태`, 이미지·영상·펜브러쉬 상태 명령과 self-test 결과를 구분하고, 진단 report에 secret·원문·파일 경로를 넣지 않음
- 선택적으로 인증된 loopback HTTP `/self-test`를 제공하되 운영 기본값은 기존처럼 HTTP API OFF 유지
- 결과를 `PASS/WARN/FAIL/SKIP`와 stable error code, latency, 실행 시각, runner version으로 요약
- `test`, release build, PD20 배포 후 self-test QUICK/INTEGRATION 실행 및 운영 문서 갱신

## 제외 범위

- 기본 명령에서 실제 GLM/Codex/Grok 생성 또는 유료 이미지·영상·펜브러쉬 job 실행
- 사용자 방에 자동 메시지·이미지·영상 전송, 카카오톡 DB 쓰기, 대화 기억 변경
- CANARY 승인 없이 `Replier.sendMessage`, `sendPhoto`, `sendVideo` 호출
- KakaoTalk 패키지(`com.kakao.talk`)·DB schema·NotificationPoller의 기존 동작 변경
- proxy-manager, proxy-conversation, proxy-codex, proxy-grok 등 서버의 package ID 변경
- 기존 JVM 단위 테스트를 self-test 하나로 대체하거나 Android UI/instrumentation 프레임워크를 무리하게 도입
- secret 값·GLM 응답 원문·대화 원문·media bytes를 report/log에 저장
- `pm uninstall`, root 파일 초기화, 운영 mode·room policy 자동 변경

## 공통 진행 규칙

- 각 Phase는 앞선 Phase의 자체 테스트와 완료 조건을 통과한 뒤에만 시작한다.
- 구현 중 발견한 이슈는 해당 Phase에서 수정·기록하고 checkbox를 실제 상태와 맞춘다.
- QUICK은 네트워크·DB 쓰기·Replier를 호출하지 않는 순수 진단으로 유지한다.
- INTEGRATION은 readiness/health와 인증·schema 검증만 수행하고 실제 생성 endpoint를 호출하지 않는다.
- DEVICE는 `/data/local/private`와 Kakao DB를 읽기 전용으로만 접근한다.
- CANARY는 명시적 관리자 확인, nonce, 시험방, capability, 요청 수 상한을 모두 검증한다.
- 모든 case에는 개별 timeout과 stable error code를 두며 하나의 hang이 전체 runner를 붙잡지 않게 한다.
- report·log·reply에는 secret, bearer, API key, 대화 원문, media bytes, 절대 경로를 기록하지 않는다.
- 기존 `ai.coreline.heybot` package, `com.kakao.talk`, room capability와 engine mode 의미를 변경하지 않는다.
- 새 의존성은 추가하지 않고 현재 Kotlin/JUnit/OkHttp/ADB·표준 라이브러리를 우선 사용한다.
- 외부 비봇 Kakao E2E는 self-test PASS와 별도 상태로 기록한다.

### 구현 태스크

- [x] manager `/ready`를 authenticated adapter로 점검한다. (개별 provider readiness fan-out은 후속)
- [x] ADB reverse `tcp:4340`와 Android process lifetime을 운영 wrapper/검증 명령으로 점검한다.
- [x] `/data/local/private` 파일 존재·symlink 금지·metadata를 읽기 전용으로 검사한다.
- [ ] DBObserver polling, NotificationPoller reflection availability, room policy·memory load 상태를 읽기 전용으로 점검한다.
- [x] `run_heybot_self_test_pd20.sh`를 추가해 APK push 후 설정 초기화 없이 실행한다.
- [ ] `self-test-stack.sh`에 Android QUICK/INTEGRATION 결과와 exit code를 연결한다.

### 자체 테스트

- [ ] 프록시 하나가 down이어도 다른 case 결과와 원인을 분리해 반환한다.
- [ ] reverse 단절·manager 401·readiness timeout이 제한 시간 내 FAIL/SKIP으로 끝난다.
- [ ] private 파일 검사에서 secret 내용과 카카오톡 DB 원문이 출력되지 않는다.
- [ ] PD20 self-test가 `ai.coreline.heybot.Main` process와 `com.kakao.talk` 보호를 확인한다.

## Phase 4. CANARY guard·문서·자동 회귀·배포 검증

### 목표

실제 외부 생성과 전송이 필요한 기능을 사고 없이 제한 검증하고, self-test를 유지 가능한 운영 기능으로 마감한다.

### 구현 태스크

- [x] CANARY 실행을 명시적 확인 전 `SKIP`하는 guard를 구현한다. (nonce·시험방·실제 provider canary는 후속)
- [ ] GLM/Codex/Grok text canary와 image/video/pen-brush canary를 서로 독립 case로 구성한다.
- [ ] 카카오톡 전송은 test room·explicit confirmation·delivery confirmation 이후에만 수행한다.
- [ ] 비용·provider auth·queue·delivery 실패를 stable code로 분류하고 자동 재시도는 하지 않는다.
- [x] Android JVM test, release build, PD20 deploy/readiness, proxy readiness, self-test report를 운영 검증으로 실행했다.
- [x] 운영 문서에 명령·권한·단계별 side effect·report 해석을 추가했다.

### 자체 테스트

- [ ] 확인 문구·nonce·시험방·capability가 하나라도 다르면 CANARY가 실행되지 않는다.
- [ ] CANARY 한 건 초과·중복 실행·재전송·외부 계정 미확인 시 SKIP/FAIL로 끝난다.
- [ ] 실제 canary 결과와 기존 unit/ready 결과가 하나의 report에 안전하게 합쳐진다.
- [x] 전체 Android test와 release build가 통과하고 PD20에서 새 package Main이 유지된다.

### 이슈 및 수정

- [ ] 발견 이슈 없음

### 완료 조건

- [ ] QUICK/INTEGRATION/DEVICE/CANARY 전체 flow 구현
- [ ] 운영 문서·자동 회귀·PD20 검증 완료

## 잔여 리스크 / 후속 과제

- 실제 비봇 Kakao 계정의 호출어·관리자·일반대화·native media delivery는 self-test PASS와 별도 E2E로 관리한다.
- CANARY는 provider 비용·OAuth 만료·카카오톡 전송 실패 가능성이 있으므로 기본 자동화에 포함하지 않는다.
- Android `app_process` 환경에서 reflection/DB 권한을 완전한 fake 없이 검증할 수 없으므로 DEVICE 결과는 PASS/WARN을 구분한다.
- proxy-manager 통합 테스트의 pending promise 문제는 self-test와 별도 서버 테스트 이슈로 추적한다.
